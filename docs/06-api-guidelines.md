# 06 — API Guidelines

## 1. Conventions

| Topic | Rule |
|-------|------|
| Base path | `/v1/...` (breaking changes → `/v2`, old version kept for ≥ 3 months) |
| Auth | `Authorization: Bearer <supabase access token>` |
| Format | JSON, `camelCase` fields |
| IDs | UUIDv7 strings |
| Time | ISO 8601 UTC (`2026-11-04T10:00:00Z`); date-only fields as `YYYY-MM-DD` with IST semantics documented |
| Money | `{ "amount": 1118000, "currency": "INR" }`, integer **paise**. *(The spec mixed rupees and paise; this fixes it.)* |
| Pagination | Cursor: `?limit=20&cursor=<opaque>` → `meta: { nextCursor, hasMore }`. Max `limit` 50 |
| Filtering/sort | Allowlisted query params only; unknown params → 400 |
| Idempotency | `Idempotency-Key: <uuid>` **required** on money endpoints, optional on other POSTs |
| Docs | OpenAPI 3 generated by **drf-spectacular** at `/v1/schema` + Swagger UI (staging only). CI publishes it, and the React repos generate types with `openapi-typescript`. |
| Trailing slashes | Django default: `/v1/orders/` (set `APPEND_SLASH` consistently; React clients use the slash) |

### Response envelope

```json
// success
{ "success": true, "data": { ... }, "error": null, "meta": { "nextCursor": "...", "hasMore": true } }

// error
{ "success": false, "data": null,
  "error": { "code": "ORDER_INVALID_TRANSITION", "message": "Order can't be approved in its current state.", "requestId": "01J..." } }
```

### Status codes

`200` OK · `201` created · `202` accepted (async) · `400` validation · `401` unauthenticated · `403` authenticated but wrong role · `404` not found **or not yours** · `409` state conflict / version mismatch · `422` business rule violation / idempotency key reuse · `429` rate limited · `5xx` server.

Error codes are stable strings (`AUTH_*`, `VALIDATION_*`, `ORDER_*`, `PAYMENT_*` …) that frontends switch on. Never parse `message`.

## 2. Required changes to the shared spec

Summary of where the spec in the chat needs to change for security and correctness. Frontends should build against these.

| Spec item | Change | Reason |
|-----------|--------|--------|
| `POST /auth/signup/complete` with `role` | Allowed only `brand` / `creator`, settable once | Prevent privilege escalation to admin |
| `POST /creators/me/social-accounts { accessToken }` | Replace with `GET /creators/me/social/:platform/connect` → OAuth redirect → server-side `/callback` | Never accept raw tokens from the client; PKCE + state; IG Graph API |
| `POST /creators/me/photos` (multipart) | `POST /uploads/presign { kind, contentType, size }` → PUT to storage → `POST /creators/me/media { uploadId }` | API never streams files; size/type enforced; async image processing |
| `wss://…/ws?token=<jwt>` | `POST /realtime/ticket` → connect with single-use ticket | JWTs in URLs leak into logs |
| `POST /orders/:id/deliverable` | `POST /orders/:id/deliverables` (versioned) | Supports revisions |
| *(missing)* | `POST /orders/:id/revisions { feedback }` (brand) | `revision_requested` had no endpoint |
| *(missing)* | `POST /orders/:id/disputes { reason }` (brand/creator) | Users need a way to raise disputes |
| *(missing)* | `POST /campaigns/:id/bids/:bidId/select` (brand) | Probably in the original spec; confirm |
| *(missing)* | `GET/POST /creators/me/payout-account` | Razorpay Route KYC onboarding; required for payouts and TDS |
| *(missing)* | `GET/PATCH /me/notification-preferences` | Email/push opt-outs |
| `POST /orders/:id/cancel` (brand or creator) | Allowed only before the first draft; afterwards → dispute | Prevent "cancel after receiving the work" abuse |
| `POST /orders/:id/approve` | Moves the order to `approved`; payout release happens async in the worker | Don't block HTTP on Razorpay; retries |
| `POST /orders/:id/pay` | Returns `{ status: "verifying" }`; the order becomes `funded` via webhook | Never trust the client callback alone |
| `GET /orders/:id/tds-certificate` | Rename to `/tds-statement` (Form 16A comes from TRACES) | Accuracy; see doc 04 |
| Tax fields on orders | Use the corrected math in doc 04 | Spec numbers were inconsistent |
| `DELETE /admin/users/:id` | `POST /admin/users/:id/deactivate { reason }` | Soft action, audited; financial history kept |
| `/admin/*` | Admin MFA (aal2) + audit log + four-eyes above a threshold for refunds/payouts | Insider / account-takeover risk |
| `GET /creators/me/campaigns` | `GET /campaigns?status=open` with role-aware filtering | Cleaner resource model; same data |
| Slug ids (`festive-snack`, `ananya-rao`) | UUIDs for ids, slugs as a separate `slug` field | Non-enumerable ids; slugs can change |

## 3. Endpoint template (how to add one)

1. **Serializers** (`serializers.py`): `XInputSerializer(StrictSerializer)` with explicit fields and `XOutputSerializer` with whitelisted fields. Annotate the view with `@extend_schema` so OpenAPI stays accurate.
2. **View** (`views.py`): `APIView`/`GenericAPIView`, with `permission_classes = [IsAuthenticated, IsBrand]`, `throttle_scope = "..."`, `@idempotent` if it moves money. `get_queryset()` uses the **scoped selector**.
3. **Service** (`services.py`): `def approve_order(*, actor: User, order_id: UUID) -> Order:` runs the policy check, then the logic in `transaction.atomic()`, then the outbox event. Keyword-only args, typed.
4. **URL** in the app's `urls.py` under `/v1/`.
5. **Tests**: service unit tests, API integration tests, an **authz matrix entry** (anon / wrong brand / wrong creator / owner / admin), an idempotency test for money endpoints, and a query-count assertion for lists.

Error handling: services raise domain exceptions (`apps/core/exceptions.py`, each with a `code` and HTTP status). The custom DRF exception handler maps them into the envelope. Never `return Response({"error": ...})` by hand.
