How every request works

Auth header

Send Authorization: Bearer <access> on everything except login and refresh. Access tokens last 15 minutes.

Response envelope

Always { success, data, error, meta }. Read data on success, error.code on failure.

Money is in paise

{ amount: 1118000, currency: "INR" } is ₹11,180. Send price and budget in paise too.

Pagination

Lists accept ?limit= (max 50). Pass meta.nextCursor as ?cursor= while meta.hasMore is true.

Strict input

Unknown fields are rejected with 400. Send only the fields listed for each endpoint.

404 means not yours too

Asking for someone else's order or campaign returns 404, so treat it as "not found or not accessible".

Login flow

OTP by SMS (Indian mobile numbers) or email. New users must finish signup once to pick brand or creator.

1 · Request a code
POST /v1/auth/otp/request/
{ "channel": "sms", "destination": "9876543210" }

→ 202 { "data": { "challengeId": "01a1…", "expiresIn": 300 } }
2 · Verify the code
POST /v1/auth/otp/verify/
{ "challengeId": "01a1…", "code": "482913" }

→ 200 { "data": { "access": "…", "refresh": "…",
  "user": { "role": null, "needsOnboarding": true } } }
3 · Finish signup (once)
POST /v1/auth/signup/complete/
{ "role": "brand", "fullName": "Priya S",
  "brandName": "Nimbu Foods" }
// creators send "displayName" instead of "brandName"
4 · Refresh before expiry
POST /v1/auth/token/refresh/
{ "refresh": "…" }

→ 200 { "data": { "access": "…", "refresh": "…" } }
// store the NEW refresh token; the old one stops working

Order status flow

Each order includes allowedActions for the current user, such as ["approve", "request_revision", "open_dispute"]. Show buttons from that list instead of hard-coding the rules.

awaiting_payment→ funded→ draft_submitted⇄ revision_requested→ approved→ completed

Other states: cancelled (before payment), refund_pending → refunded (cancelled after payment), disputed (ops team decides). Payment is not live yet: in dev, use the simulate-payment endpoint to move an order to funded.

Error codes to handle

Switch on error.code. The message is safe to show but may change.

CodeHTTPWhat to do
AUTH_REQUIRED / AUTH_INVALID401Refresh the token once; if that fails, send the user to login.
VALIDATION_ERROR400Show error.details next to each field.
OTP_INVALID400Wrong or expired code. Let the user retry or request a new one.
RATE_LIMITED429Too many tries. Wait for the Retry-After seconds before retrying.
FORBIDDEN403Wrong account type for this screen (e.g. a creator calling a brand endpoint).
NOT_FOUND404Missing, or not this user's resource.
ORDER_INVALID_TRANSITION409The order moved on. Refetch it and re-render allowedActions.
SIGNUP_ALREADY_COMPLETE409Skip onboarding; go to the home screen.
BID_EXISTS · OFFER_NOT_PENDING · BID_NOT_PENDING409Refetch and show the current state.
CART_EMPTY · ORDER_NOT_COMPLETED · INVALID_PHONE422Show the message to the user.
OTP_DELIVERY_FAILED503SMS/email provider is down. Ask the user to retry shortly.
